# Reproducibility Artifact: Programmable Cloud Continuum for Distributed CPS

This repository contains the complete research artifact for the paper "A Programmable Cloud Continuum Infrastructure for Distributed CPS Experimentation". It includes the orchestration scripts, deployment manifests, and sample experimental data required to reproduce the Renewable Energy Community (REC) and AirWatch monitoring use cases.

## Repository Structure

- `infrastructure/s4t-local/`: Scripts and manifests to deploy the Stack4Things (S4T) substrate on a local K3s cluster.
- `experiments/`:
  - `simulation/`: Manifests and code for the REC control use case.
  - `airwatch/`: Manifests and code for the AirWatch monitoring use case.
- `kubeconfigs/`: Directory to place your cluster credentials (see `kubeconfigs/README.md`).
- `results-sample/`: A descriptive guide of the expected output format and data schema generated by the campaign.
- `deploy-continuum.sh`: Master orchestrator to instantiate the software stack across Edge, Fog, and Cloud tiers.
- `campaign_runner.sh`: Automation script to execute independent experimental runs.

## Prerequisites

1.  **Infrastructure Access:** Access to a distributed infrastructure (e.g., SLICES, private clusters) with at least three sites (Edge, Fog, Cloud).
2.  **K3s/Kubernetes:** Lightweight Kubernetes (K3s) installed on all compute nodes.
3.  **Docker & Helm:** Tools for containerization and package management.
4.  **Network Overlay:** Secure connectivity between sites (the artifact assumes Tailscale/WireGuard as described in the paper).

## Setup Instructions

### 1. Bootstrap the Substrate
Navigate to `infrastructure/s4t-local/` and run the automated deployment to install Stack4Things on your local gateway:
```bash
bash automated_deployment.sh
```

### 2. Configure Kubeconfigs
Place the `kubeconfig` files for your sites in the `kubeconfigs/` directory:
- `cloud-cloud.yaml`: SLICES Cloud cluster.
- `fog-fog.yaml`: Fog cluster in Fog.
- `edge-local.yaml`: Local Edge cluster in Edge.
- `fog-local.yaml`: Local Edge cluster in Fog.

### 3. Deploy the Continuum
Use the master script to deploy the full software stack (Kafka, Spark, Mosquitto, and application logic):
```bash
./deploy-continuum.sh --registry <your-docker-registry>
```

> **Important:** All static IP addresses have been replaced with placeholders like `<CLOUD_IP>`, `<FOG_IP>`, or `<EDGE_GATEWAY_IP>`. Ensure these are correctly resolved via your network overlay (e.g., Tailscale/WireGuard) or update the environment variables in your `.env` file.

### 4. Run the Experimental Campaign
Execute the automated campaign runner to reproduce the results:
```bash
./campaign_runner.sh
```

## Data Extraction and Analysis
The campaign runner automatically extracts logs and metrics into a `results-campaign/` directory. You can compare your results with the provided samples in `results-sample/`.
